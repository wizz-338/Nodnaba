아래 지시문과 첨부 PNG9개를 기준으로 기존 마노 게임을 수정해줘.
이 문서는 단순 기획 제안이 아니라 실제 전달 이미지의 사용 지시다. 기존 프로젝트 구조부터 확인하고, 가능한 부분부터 구현을 끝내줘. 이미지를 새 임시 도형이나 다른 캐릭터로 대체하지 마.

[작업 범위]
기존 사이트의 마노 DEMO 게임과 관련 메뉴·뉴스·마노 프로필의 시각 자산을 이 패키지로 교체한다. 기존 사이트의 라우팅·계정·저장 데이터·다른 페이지를 보존한다. DEMO 표기는 유지한다. 기존 서버나 배포 설정을 멋대로 교체하지 않는다. 이 패키지의 ASSET_PREVIEW.html은 자산 확인용이며 완성 게임으로 연결하거나 배포하지 않는다.

[실제 자산 데이터 사용]
맨아래 JSON은 assets.json 내용이다. 그대로 프로젝트 데이터 파일로 만들고 frame.rect로 잘라 쓴다. frame.pivot은 원본 셀 안의 픽셀 좌표다. 예: drawX=worldX-pivotX*scale, drawY=worldY-pivotY*scale. frame.contentBounds는 셀 안에 실제 그림이 차지하는 영역이다. 매 프레임 그림 경계를 다시 trim해서 크기를 맞추지 않는다. 원본 생성 시트는 간격이 일정하지 않으므로 sources/를 균등분할하지 않는다.
PNG에는 alpha가 있다. 미리보기 배경을 캐릭터 이미지로 오해하여 검은색/체크무늬를 덧그리지 않는다.
Canvas imageSmoothingEnabled=false, CSS image-rendering:pixelated를 기본으로 한다. HTML UI 글자는 일반 가독성 좋은 폰트로 표시한다. 스프라이트에 글자를 합성하지 않는다.
프레임의 화상을 충돌판정으로 사용하지 말고 별도 원형/타원형 collider를 둔다.

[마노]
최종화면360×640 기준 실제 캐릭터 실루엣 높이40~46px를 목표로 한다. 시트64셀의 전체 투명 영역까지 캐릭터 높이로 오해하지 말고 contentBounds로 확인한다. 그림 전체를 무작정100px 이상 키우지 않는다.
이동은 조이스틱 입력벡터의 연속적인360도 방향으로 처리한다.8방향은 보이는 원화 선택에만 사용한다. 대각 이동속도를 정규화하고 관절 부위 분리회전이나 캐릭터 전체 회전으로 방향을 대신하지 않는다.
전방향 이미지는5방향 생성+3방향 반전이다. 여덟 방향 모두 별도 원화라고 표시하지 않는다. 첨부 시트에 좌측 반전 프레임까지 이미 들어 있으므로 달리기에서 이중반전하지 않는다.
run frameMs=90을 시작값으로 한다. 속도에 맞게 재생율을 조절하고 정지 즉시 idle로 전환한다. 발기준점은 고정하고 공중 프레임에서1px 이내 시각적 상하 움직임은 가능하다. 관성으로 미끄러지는 움직임을 넣지 않는다. 방향 경계에서 그림이 떨리지 않게 작은 히스테리시스만 둔다.
idle S/SE/E는2프레임. NE/N은1프레임. SW/W/NW는 해당 우측 idle을 반전한다. JSON에 없는 프레임 이름을 요청하지 않는다.
피격은 S/SE2프레임씩. 다른 방향에서 갑자기 정면으로 돌아서지 말고 현재프레임+짧은 색상 플래시로 표현한다. 다운은 down_0→down_1→down_2 후 마지막 유지. down_3은 회복/결과 연출용이다.
작은 프레임별 얼굴/발/꼬리 차이는 생성 원화의 현재 한계다. 이미지 변경 없이 이동속도·발접점·전환 타이밍으로 먼저 조율하고, 중대한 튐이 남으면 해당 프레임만 수정 대상으로 명확히 보고한다.

[전투 규칙]

무기는 데이터 중심으로 구성해 나중에 츄르/비눗방울/딸랑이를 추가할 수 있게 하되 이번 화면에 잠금 슬롯을 늘어놓지 않는다.
적이 여러 방향에서 접근하고 마노는 이동으로 회피한다. 적 처치시 경험치/코인. 경험치 레벨업은 전투를 멈추고 삼지선다를 띄운다. 웨이브/스테이지 진행과 피격/패배/재시작이 실제로 작동해야 한다.

[탱탱볼]
자동 타겟 선택→직선 발사→충돌→실제 반사/다음표적 방향으로 궤도 갱신. 이미지 미리보기의 공 위치는 정적인 배치 예이며 공전 궤도를 구현하라는 뜻이 아니다.
공 표시지름6~8px에서 시작. 초기동시표시2~4개 정도. trail은 공 뒤짧은8~16px, 충돌은impact_0..3 총120ms 안팎. 공마다 화면을 가로지르는 무지개/긴곡선/빛기둥 금지.
분열은 ball_child 사용. 분열 자식이 즉시 무한재귀 분열하지 않도록 세대/확률을 데이터로 관리한다. 동일 적에 같은 공이 매프레임 중복피해를 주지 않게 재타격 대기시간을 둔다.
핵심 강화는 중복 선택 가능하게 한다. 증식은+1이 아니라 ×2, 공격간격×0.7, 피해×1.35가 서로 곱해지는 성장.1→2→4→8→16→32의 실제 전투효과를 유지한다. UI만 강해지고 실제공은10개로 고정되는 식의 숨은 너프를 넣지 않는다.
성능은 pool/공간분할/적절한 수명/짧은FX로 해결한다. 표현용 FX 개수 제한은 가능하지만 실제공/피해의 성장을 몰래 없애지 않는다. 성능상 제한이 필요하면 수치와 영향부터 명확히 보고한다.
초반은 쉬우며 이후 평균빌드는 막히고 핵심옵션 중복행운으로 상위스테이지를 뚫을 수 있게 실제 테스트한다. 정확한 난이도 수치는 기존 플레이데이터를 보고 조정하며 아트패키지만으로 밸런스가 검증되었다고 주장하지 않는다.

[적/전장]
임프는 추적형, 거미는 재빠른 접근형, 악마슬라임은 느린 압박형, 해골짐승은 빠른 직선 접근형으로 구분한다. 원화는 우측기반4프레임이므로 좌우반전까지 사용하고 북향별도 프레임은 있다고 가정하지 않는다.
보너스도둑은 보상자루 실루엣을 살리고 처치시 보상을 준다. 보스는 보통몹보다1.8배 안팎 실루엣으로 배치, 준비동작+바닥 경고 후 돌진. 경고는 코드로 원/부채꼴/선의 실제 판정영역을 그린다. 아트 이미지를 판정과 무관하게 확대해 경고로 쓰지 않는다.
일반몹 피격/사망은 짧은 플래시와dust_0..2로 처리. 보스 다운 원화는 별도 제공한다.
전장은 평평하고 탁 트여야 한다. 분수/벤치/공원 장식/충돌없는 가짜벽을 추가하지 않는다. 바닥은 낮은 대비를 유지한다.09_ground는 전체화면 배경 또는 mirror-repeat로 사용한다. 무조건 seamless라고 가정하지 않는다.
마노·적은 발위치로 깊이정렬한다. 드랍은 바닥 위, 공/타격은 개체 위, 위험 경고는 바닥 위·개체 아래에 둔다.
