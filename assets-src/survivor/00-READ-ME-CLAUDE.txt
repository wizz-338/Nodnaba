마노 MVP — ZIP 없이 Claude에 전달하는 통합 명령서

이 TXT와 01~07 PNG 총8개 파일을 함께 받았다면 아래대로 기존 사이트에 적용한다. ZIP을 요구하지 않는다. 그림을 다시 생성하지 않는다.

[최신 지시 — 아래 기존 문서의 충돌 문구보다 우선]
게임 화면만 구현하면 끝이 아니다. 기존 사이트의 게임 메뉴에 소개/썸네일/실행 링크를 반영하고, 뉴스에 추가/업데이트 소식을 기존 형식에 맞춰 작성해 연결하고, 마노 프로필에도 관련 게임과 실행 링크를 추가한다. 세 곳의 이름/대표 이미지/설명/링크를 일치시킨다. DEMO 표기 및 다른 콘텐츠와 기존 저장 데이터를 보존한다. 기존 메뉴/뉴스 유지라는 문구는 이번 게임 관련 변경 금지를 뜻하지 않는다. 기존 게임 링크나 기능을 임의로 덮어쓰지 않는다.

이 자료는 아트와 기획이고, 실제 코딩과 검증은 Claude가 담당한다. 계획 설명으로 끝내지 말고 플레이 가능한 상태까지 구현한다.

[이미지 취급]
01~04는 그대로 사용 가능한 마노 시트다. 05는 괴물 시트들을 수직 배치한 무손실 PNG, 06은 아이콘과 효과를 모은 무손실 PNG다. 아래 crop은 원본 픽셀 기준 [left,top,right,bottom], right/bottom 제외이다. 코드 실행 환경에서 파일을 직접 열어 잘라 원래 경로로 복원한다. 채팅 화면의 축소 썸네일이나 스크린샷을 잘라 쓰지 않는다. 07은 원본 바닥이다.
이 버전은 사전 합성 시트만 사용하며 원본 컷아웃 파츠/리그/참고 그림/프리뷰는 전송하지 않는다. 해당 파일을 찾거나 요구하지 않는다. 원본 이미지 파일 접근이 불가능하면 접근 불가를 정확히 알리고 임의 대체 그림으로 완성했다고 하지 않는다.

# 마노 모바일 액션 로그라이트 — 통합 구현 지시서

## 0. 작업의 성격
사용자가 요청한 최종 목표는 모바일 세로형 플레이어블 MVP다. ChatGPT는 디자인·아트·기획·이 지시서를 담당했다. Claude가 실제 코딩, 기존 프로젝트 적용, 실행, 테스트를 담당한다. 이 패키지는 실행 게임이 아니라 구현용 자산과 명세다. 별도 사이트 생성이나 무단 배포, 기존 게임/저장 데이터 삭제를 하지 않는다. 기존 DEMO 표기·메뉴·뉴스·아티스트 링크·주소는 유지하고 게임 내부를 수정한다. 현재 저장 구조와 게임 라우트부터 조사하고 기존 마노 관찰/마을 기능이 존재하면 그 데이터를 보존한다. 전투를 넣는 과정에서 기존 기능의 제거를 임의로 결정하지 않는다.

## 1. 읽는 순서
1. 이 파일.
2. ART_AND_ANIMATION.md — 실제 파일, 시트 행/열, 방향, 조립 및 UI.
3. COMBAT_AND_GROWTH.md — 판정과 강화.
4. SCREENS_AND_PROGRESS.md — 화면과 장비/합성/저장.
5. VALIDATION.md — 완료 기준.
6. data/*.json — 구체적인 초기 수치와 메타데이터. manifest.json으로 파일 목록 확인.

우선 요구사항과 수치는 구분한다. 이동만/무기 1칸/마노 외형/괴물 적/평지/중복 강화는 확정 요구다. 6웨이브·시간·피해·확률·등급 배수 등은 이번 MVP를 구현 가능하게 만든 초기 제안값이다. 테스트에서 벽의 위치가 어긋나면 원래 철학을 지키며 조정하고 변경 내용을 보고한다. 검증 없이 실제 승률을 주장하지 않는다.

## 2. 핵심 요구사항
- 모바일 9:16. 화면 드래그 가상 조이스틱으로 이동만 조작한다. 조준/공격 자동. 공격 버튼, 대시 버튼 없음.
- 전투 주체는 마노 한 명, 장착 무기 슬롯 하나. 탱탱볼부터 완성한다.
- 비픽셀의 부드러운 2D SD 아트. 캐릭터의 고양이 얼굴 후드, 검정 단발, 크림 배, 빨간 목줄 보존.
- 단순 평지, 적은 괴물. 장식/공원/분수/장애물 과다 금지.
- 이동 좌표는 360도 연속. 외형은 8방향 애니메이션. 전체 그림을 진행 방향 각도로 눕히지 않는다.
- 초반 적응 구간 이후 성장 벽. 같은 핵심 강화가 반복 출현하여 좋은 운으로 평소 못 넘는 구간을 돌파할 수 있어야 한다.
- 짧은 충돌 효과와 짧은 공 잔상만. 거대한 무지개 궤적 금지.

## 3. 실제 아트 적용
권장 경로는 assets/mano/sheets/의 사전 합성된 시트다. 모든 시트 128px 정사각 셀, 행 순서 S, SW, W, NW, N, NE, E, SE. walk 12프레임, idle 6, hit 4, down 8. data/mano.json이 정확한 값의 기준이다. PNG들을 다시 자르거나 생성할 필요 없다. 시트 소스는 동봉된 파츠를 실제 조립해 만든 것이며 손그림 연속 프레임 방식은 아니다.

원한다면 동일 메타의 rigs와 assets/mano/parts를 이용해 런타임 컷아웃 보행으로 교체할 수 있다. 단, 시트와 파츠를 동시에 겹쳐서 렌더하지 않는다. 프레임 시트를 먼저 적용하는 것이 MVP 우선이다.

적 3종은 assets/enemies/*-move/hit/die.png를 사용한다. 이동은 정지 원화에 squash/bob을 적용한 경량 애니메이션이다. 복잡한 사족 보행을 구현한 것으로 과장하지 않는다. 모든 효과의 배경은 투명, 바닥만 불투명이다.

## 4. 구현 구조 제안
기존 프로젝트 구조를 우선 존중하되 다음 역할을 분리한다.
- assets/: 본 패키지의 렌더 자산.
- data/: 무기, 강화, 웨이브, 적, 장비 등급, 렌더 메타.
- scenes/: 장비/전투/강화 모달/결과/합성.
- systems/: 입력, 자동 조준, 무기 행동, 이동/충돌, 드랍/XP, 웨이브, 저장.
- render/: 아틀라스 재생, 카메라/좌표, UI, 효과.
- tests/: 저장/보상 중복/확률/성장/조작 회귀 검증.
무기 행동은 behaviorId 레지스트리로 분리한다. 무기 정의 하나에 공격 방식을 하드코딩하지 않는다. 미래의 츄르는 summon_cats 유형으로 확장할 수 있도록 한다. 아직 구현하지 않은 무기는 장비 목록이나 보상에 노출하지 않는다.

## 5. 입력/상태 전환
BOOT → EQUIPMENT → COMBAT ↔ LEVEL_UP, COMBAT ↔ PAUSE, COMBAT → RESULT → EQUIPMENT. 합성은 EQUIPMENT에서 진입한다. 강화/일시정지 중 전투 시간, 발사, 적, 공, 무적 타이머 모두 정지한다. 모달을 닫을 때 조이스틱 상태를 초기화한다. pointercancel, 포커스 상실, 화면 잠금/백그라운드 전환에서도 입력을 해제한다. 레벨업이 연속으로 가능한 경우 XP를 버리지 않고 다음 선택을 순서대로 연다.

## 6. 완료 보고
구현한 것, 수정한 수치, 테스트 결과, 남은 한계를 짧게 구분해 보고한다. 실제 테스트하지 않은 FPS/승률/터치 경험을 검증 완료로 쓰지 않는다. 사용자에게 새 이미지 제작이나 파일 분리 작업을 떠넘기지 말고 이 패키지를 그대로 사용해 전투 MVP를 완성한다.

# 아트·애니메이션·UI 명세

## 자산 상태
- 마노: 서로 다른 5방향 파츠(S, SE, E, NE, N), 좌우 반전 3방향(SW, W, NW), 총 8방향 시트. 반전 방향에서는 광원과 작은 비대칭도 반전된다. 이것은 MVP의 명시적인 절충이다.
- walk 12×8=96, idle 6×8=48, hit 4×8=32, down 8×8=64, 총 240개 셀. 각 128×128.
- 원본 파츠 6개×5방향=30 PNG. 시트 재생을 쓰면 파츠를 런타임에 따로 로드하지 않아도 된다.
- 괴물 3종, 각 정지 PNG와 move/hit/die 시트. 6/3/5 프레임, 각 셀 128.
- 아이콘 16개, 128×128 투명 PNG. 실제 투사체는 ball.png를 작게 쓴다. split_balls.png는 분열 묶음 아이콘이며, 실제 자식탄은 ball.png 개별 객체로 렌더한다.
- 효과 impact/dust 각각 4프레임 시트, 셀 128. 페이드/크기 변화로 만든 프레임이다.
- 바닥 ground.png. UI SVG 8종. UI 글자는 이미지에 굽지 않고 DOM 또는 텍스트 렌더로 표시한다.

## 방향/재생
스크린 좌표 x 오른쪽, y 아래. atan2(dy,dx)를 사용한다. E=0°, SE=45°, S=90°, SW=135°, W=180°, NW=-135°, N=-90°, NE=-45°. 각도 구간 폭 45°. 기존 구간에서 6° 이상 벗어났을 때 바꿔 경계 진동을 막는다.
마노 groundAnchor=[64,115.5]를 월드 위치에 맞춘다. 셀 중심을 월드 위치에 맞추면 발이 떠 보이므로 금지. 원화의 실제 높이는 셀 약 80%다. 논리 화면에서 셀 64px 내외로 표시하여 캐릭터 실높이 약 48~52px를 얻는다. 적은 data/balance.json의 실높이로 맞춘다.
걷기 한 사이클 .72초. 속도 비율로 위상을 진행하되 0.7~1.5배 이내. 방향 전환 시 normalized phase 유지. idle 1.2초, hit .18초, down .55초. hit 동안 이동 로직을 멈추지 않는다. 무적 점멸과 짧은 색상 tint는 런타임 효과. 시트가 이미 있는 hit 상태를 억지로 바꾸지 않아도 된다.
프레임 간 형태를 자동 모핑하지 않는다. 12프레임 보행을 정상 주기로 재생하고 위치 보간으로 부드러움을 얻는다. 방향 전환에서 두 실루엣을 오랫동안 반투명 겹치지 않는다.
모든 시트는 content-aware trim 금지. 셀 좌표 고정. 손상 없이 PNG RGBA와 imageSmoothing을 유지한다.

## 리그를 직접 쓰는 경우
data/mano.json의 rigs 각 항목: size는 512×512 조립캔버스에서 부품 크기, pivot은 정규화 회전중심, joint는 그 pivot의 좌표. z는 drawOrder를 따른다. 전체를 먼저 조립한 뒤 월드 표시 배율 적용. 팔·다리 회전은 ±8~11°, 어깨와 골반 겹침 확보. S/N은 다리 회전 ±4°와 높이 차이로 움직임을 줄인다. 직접 리그 재생도 동일 phase를 유지한다.

## 화면과 UI
논리 360×640. 실제 디바이스는 aspect-fit, 남는 영역은 단색 배경. Safe area를 적용하되 화면 비율을 강제로 늘이지 않는다. 가로 기기는 중앙 세로 뷰포트를 제공한다.
상단 HUD에는 체력/XP, 레벨, 웨이브/남은시간, 재화, 일시정지만. 장비·합성 버튼을 전투 위에 띄우지 않는다.
가상 조이스틱은 하단에서 누른 지점에 생기는 floating 방식. 버튼은 이동용 하나뿐이다. 조이스틱 표현은 hitbox를 막지 않고, UI 밖 입력만 받는다. data/ui.json에 위치/색/반경 참조.
강화 카드: 화면 중앙, 가로로 3개를 좁게 놓지 말고 세로 3장. 이름, 현재 중첩 수, 실제 수치 변화만. 카드 높이 90 내외, 간격12. 선택 전까지 전투 정지. 더블탭/중복선택 방지.
장비: 마노 미리보기, 무기 슬롯 한 칸, 현재 등급/피해, 보유 무기 목록, 출발 버튼. 같은 무기 여러 개를 보유하는 것과 동시 장착은 별개.
결과: 클리어/실패, 도달 웨이브, 처치, 재화, 빌드 요약, 다시 도전/장비로. 클리어에서 상자 1개 지급.
합성: 같은 무기·같은 등급 3개 → 상위 1개. 결과 등급 미리보기와 소비 3개를 표시. 실제 합성 액션은 한 번만 커밋한다.
등급 D/C/B/A/S/SS/SSS/EX 색은 data/ui.json. EX도 무지개 애니메이션 대신 고정 청록 테두리로 가독성 유지.

## 바닥
생성 이미지의 가장자리가 수학적으로 seamless라고 보장되지 않는다. MVP 고정 아레나에서는 단일 ground.png를 전장 전체에 cover로 깔아 이음매를 없앤다. 무한 스크롤 타일맵으로 임의 확장하지 않는다. 필요 시 불투명도 .35~.5를 바탕색 위에 적용해 입자 대비를 낮춘다. 충돌 장애물은 없음.

# 전투·복리 성장

## 전장과 판정
MVP 전장은 화면 안 고정 평지. data/balance.json의 bounds 안에서 이동. 시점은 시각적으로 약한 쿼터뷰지만 이동/충돌은 2D 원형 판정이다. 적은 모든 경계 방향에서 고르게 생성하되 플레이어와 60px 미만이면 다른 위치를 선택한다. 생성 0.35초 예고 후 접촉 활성화. 스폰이 아예 막히면 잠깐 대기하고 플레이어 위에 강제 생성하지 않는다.
적은 플레이어 추적, 서로 너무 뭉치지 않게 약한 분리력. 적 140 soft limit에서 생성 타이머를 멈추고 화면 밖에 무한 대기열을 쌓지 않는다. 프레임 적체 후 한 번에 몰아 생성하지 않는다. 모든 속도와 타이머는 초 기준. 물리 fixed-step 또는 delta 제한을 사용한다.
플레이어 hitRadius 9. 접촉 피해 후 .65초 무적. 한 틱에 여러 적이 겹쳐도 동일 이벤트에서 체력을 반복 차감하지 않는다. 체력 0에서는 사망 상태로 잠그고 결과/보상을 한 번만 처리.

## 탱탱볼
슬롯 하나, 가장 가까운 유효 적을 자동 조준. 적이 없으면 발사하지 않는다. 기본 1.1초마다 공 하나, 공 반경4.5px, 속도260px/s, 피해14. 생성 위치는 플레이어 중심에서 적 방향으로 약12px. 같은 표적에 갇혀 즉시 연속 명중하지 않도록 enemyId별 .18초 재충돌 제한을 둔다.
벽 반사: 접촉 법선으로 속도 반전, 경계 안으로 위치 보정. 적 반사: 충돌 법선 기준 반사 후 겹침 밖으로 밀어내기. 동일 프레임 다시 충돌하는 루프 금지. 추가 반사 bounces=2는 첫 명중/접촉 후 최대2회 더 반사할 수 있다는 뜻이다. 반사 예산을 소모했으면 다음 충돌에서 공 제거. 무조건 bounces+1명의 적을 때린다는 뜻은 아니다.
공 수명은 base ttl3.2초에 반사2회당 .3초씩 더하되 최대5.3초. 고속/큰 dt에 적을 통과하지 않도록 swept circle 또는 5px 이하 서브스텝. 공끼리 충돌하지 않음.
멀티볼은 좁은 부채꼴, 최대 발사각60°. 개수 많다고 전방향 완전 방사를 기본으로 바꾸지 않는다. 잔상은 이전 .03~.05초 이동거리만, 저불투명도. 화면 횡단 선 금지.

## 분열
부모 공의 첫 적 명중에서만 한 번 검사. p=splitChance. floor(p)회 확정 분열 + 소수부 확률로1회 추가. 1회에 자식2개, 각각 부모피해45%, 반경75%, 반사1회, 수명1.4초. 자식은 재분열하지 않는다. 벽 명중에서는 분열하지 않는다. 같은 적의 내부에 태어나 즉시 피해가 중복되지 않게 충돌 밖에서 생성하고 해당 적에 짧은 재타격 잠금 적용. 최대 p=2는 두 번 확정 분열(자식4개).

## XP와 삼지선다
처치 시 XP, 30%로 재화1 드랍. 획득 반경 안에서 끌려오며 실제 접촉 시 획득. 화면 파티클 정리 때문에 XP를 잃지 않는다. 드랍이 많아지면 가까운 XP를 합쳐 총량 보존.
레벨업 때 전투 완전 정지. 그 레벨 카드3개는 서로 다르게 가중 추첨. 이전 레벨에 고른 옵션은 다음 레벨 풀에서 빼지 않는다. 선택 한 번에 반드시 수치 반영. damage는 항상 현재값 ×1.30, haste는 현재 간격 ×.85라서 중첩 효과가 실제로 누적된다.
상한에 도달한 옵션은 풀에서 제외한다. 최대 count10, bounces16, split2, 최소간격.15초, radius14, pickupRadius160. health와 damage는 상한 없이 남긴다. 카드에 현재값→선택 후 값을 보여준다. 최대치 도달 후 효력 없는 카드가 다시 등장하면 실패.

## 복리 체감의 근거와 검증
첫 명중 기준 원시 DPS는 damage×count/interval이다. 기본 14/1.1≈12.73. 예를 들어 8선택에서 count2회, damage3회, haste2회, split1회를 고르면 분열 제외 원시 DPS가 3×1.3³÷.85²≈9.12배다. 반사는 추가 명중 기회를, 분열은 추가 피해/범위를 제공하므로 조합의 가치가 달라진다. 이 계산은 적중률과 적 배치, 오버킬을 제외한 이론값이며 실제 승률 증거가 아니다.
평균 운/좋은 운의 벽은 실플레이에서 확인해야 한다. 지정 빌드로 강제 선택한 테스트와 자연 추첨을 나눠 검증한다. 반복 핵심 카드가 붙었는데도 생존/처치 효율이 거의 동일하면 충돌 또는 성장 적용 오류부터 조사한다. 운이 좋을수록 반드시 이기는 조작 불필요 게임으로 만들지는 않는다.

## 웨이브
기본 챕터 6웨이브, 총210초(강화/일시정지 시간 제외). 시간 생존 시 다음 웨이브, 잔여 적은 유지, 체력15회복. 6웨이브 종료 시 챕터 클리어. 보스 원화는 이번 범위에 없으므로 임의 보스/추가 아트 제작으로 MVP를 지연시키지 않는다. 다음 챕터는 HP/접촉피해/스폰 간격을 data 값으로 조정.
1~2웨이브는 적응, 3~4에서 압박, 5~6에서 빌드 차이가 드러나는 초기 목표. 실제로 모든 빌드가 쉽게 깨거나 전부 실패하면 수치를 조정한다. 체력/속도 증가를 동시에 무작정 올려 회피 불가능한 벽을 만들지 않는다.

## 성능
오브젝트 풀, 공간 분할 충돌, 화면 숫자/장식 파티클 개수 제한. 논리 투사체를 몰래 삭제해 성능을 맞추지 않는다. 높은 빌드에서 먼저 잔상과 피해 숫자를 줄인다. 장치 한계로 판정 축소가 필요하면 그 정책과 손실을 보고하고 임의 성능 저하를 숨기지 않는다.

# 화면·전투 밖 성장·저장

## 화면 목록과 표시 문구
- 장비: 「마노의 주머니」, 무기 슬롯1개, 「탱탱볼」, 등급, 「장착 중」, 「합성」, 「출발」.
- 전투: LV, WAVE, 남은 초, 체력바/XP바, 재화, 일시정지. 조작 안내는 첫 판 시작 후3초만 작게 표시.
- 강화: 「이번 판의 행운은?」, 「하나를 골라 주세요」, 카드별 이름/아이콘/중첩/현재→다음값.
- 일시정지: 「잠깐 쉬어가기」, 「계속하기」, 「장비로」. 장비로 나갈 때 전투 포기 확인.
- 결과: 「마노가 해냈다!」 또는 「한 번 더 도전할까?」, 챕터/웨이브/처치/재화, 선택 빌드, 「다시 도전」/「장비로」.
- 보상: 「상자 열기」, 획득 무기 등급, 「확인」. 슬롯이 늘어나는 것이 아님.
- 합성: 「같은 무기 3개를 모아 더 높게」, 소비3개와 결과1개. 불충분/EX는 비활성 이유 표시.

## 장비
무기 기본 정의는 data/weapons.json. 무기 인스턴스는 고유 ID, weaponId, grade를 가진다. 전투 시작 시 장착 인스턴스의 등급 피해 배수를 적용하고 전투 스탯을 새 객체로 복사한다. 전투 중 강화는 원본 장비에 누적 저장하지 않는다. 매판 초기화되는 전투 성장과 영구 등급을 혼동하지 않는다.
초기 지급 D 탱탱볼1개. 한 슬롯만 장착. 아직 다른 무기를 구현하지 않았으므로 상자의 무기 종류는 탱탱볼만이며 등급 D90/C9/B1 확률이 무작위 요소다. 실제로 4종 무기가 있다고 표시하지 않는다. 츄르 등은 후속 확장 지점만 준비한다.

## 합성
같은 weaponId, 같은 grade 인스턴스3개를 소모하고 다음 grade1개 생성. D→C→B→A→S→SS→SSS→EX. EX 합성 불가. 비용0은 이번 MVP 기본값. 등급 피해 배수는 progression.json.
장착 중인 인스턴스는 자동 선택하지 않는다. 사용자가 명시적으로 포함했다면 결과 아이템 자동 장착 여부를 표시하고, transaction 내에서 결과로 교체한다. 버튼 연타/새로고침/다중 탭으로 중복 지급되면 안 된다. 수량이 부족하면 기존3개를 먼저 지운 후 실패하는 구조 금지.

## 보상과 저장
챕터 클리어당 상자1개, 실패에는 상자 없음. 재화는 전투 결과 집계 후 획득분 저장하며 이번 MVP에서는 소비처가 없다. 소비처를 새로 지어내지 않는다.
기존 저장소를 지우거나 기존 키를 갈아엎지 않는다. versioned namespace를 새로 쓰되 기존 시스템의 소유권을 확인한다. schemaVersion, inventory, equippedInstanceId, currency, unlockedChapter, lastAwardedRunIds, bestResults를 저장. runId를 발급하고 결과 보상은 idempotent하게 한 번만 지급.
탭 종료 시 진행 중 전투 복구는 MVP 필수 아님: 재접속 시 미완료 판은 종료, 영구 장비/확정 보상은 보존. 시작 화면에 동작을 명확히 해 사용자 진행을 소리 없이 날리지 않는다. 저장 실패(사생활 모드/용량 등)는 플레이를 중단하지 말고 저장되지 않았음을 알린다.

## UI 구현 메모
패널/바/버튼은 data/ui.json의 색과 모서리 값을 적용한 DOM/CSS가 기본. SVG는 참고/작은 버튼/조이스틱용이다. card.svg를 긴 직사각형에 무조건 stretch해 모서리를 찌그러뜨리지 않는다. 글자는 라이브 텍스트로 렌더하며 폰의 한국어 시스템 글꼴을 사용.

# 완료 기준과 확인 기록

## 이 패키지에서 확인하는 것
- 명시된 PNG/SVG/JSON이 실제 존재하는가.
- 투명 자산에 alpha=0 배경이 있고, 시트 크기가 셀×행/열과 일치하는가.
- 마노8방향의 실제 파츠 조립 외형, 정지와 반대 보행 위상, 밝은 배경/작은 크기에서 확인.
- 프리뷰는 실제 자산에서 합성, 홍보 원화가 아님.
- 미검증: Claude 코드 적용, 실기기 터치, 프레임률, 난이도별 실승률, 게임 저장 트랜잭션.

## Claude 적용 후 필수
1. 조이스틱 어느 각도든 이동, 화면 밖 드래그/손떼기/두 번째 손가락/취소/백그라운드에서도 입력 고착 없음.
2. 대각선 최대 속도는 수평과 동일. 외형 방향만8개이며 이동은8방향으로 제한하지 않음.
3. 걷기 위상을 유지한 방향전환, 발밑 anchor 안정, 프레임 잘림/투명구멍/두 파츠 중복 렌더 없음.
4. 공 첫 명중, 벽 반사, 적 반사, 예산 소모, 수명 종료. 큰 dt에도 적을 관통해 무시하지 않음.
5. 분열 p=0/.25/1/1.25/2의 기대 자식 수와 실제 생성을 확인. 자식은 절대 재분열하지 않음.
6. 삼지선다 안에서는 서로 다른3개, 다음 레벨 같은 옵션 재등장. 상한 옵션 제외. 선택 연타에도 한 번 반영.
7. damage3회=기본×1.3³, haste2회=기본×.85², count2회=3개. 부동소수 오차 허용.
8. XP 초과량 유지, 연속 레벨업, 일시정지와 강화 중 모든 전투 타이머 정지.
9. 챕터 성공/실패/재시작, 결과 보상1회. 재시작은 전투 강화 초기화, 영구 장비 유지.
10. 동일 무기/등급3개만 합성, EX 비활성, 장착아이템 처리, 클릭 연타/리로드에서도 중복 보상 없음.
11. 기존 게임 저장/라우트/메뉴/뉴스 보존.
12. 360×640 논리 화면을 다양한 모바일 크기에 맞춰 HUD와 손가락이 전투를 가리지 않음.

## 난이도 검증
동일 조작 정책으로 최소 세 비교를 수행: (A) 생존/유틸 중심, (B) 골고루 강화, (C) count/damage/haste/split 집중 반복. 개발용 seed와 강제 카드 선택은 사용자 UI에 노출하지 않는다. 일반 모드 추첨은 정해진 가중치대로 유지한다.
자연 추첨 여러 판의 도달 웨이브/선택 기록/사망시간/처치량을 수집. 최소30판은 초기 경향용일 뿐 확정 승률로 주장하지 않는다. C가 B보다 유의미하게 늦게 막히거나 클리어하는지 확인. 평균 빌드도 전부 쉽게 깨면 중후반 난이도 조정, C도 초반에 전부 막히면 난이도/드랍/공 판정부터 조사.

## 성능 검증
실제 Android 브라우저에서 적100~140, 투사체200 조건의 프레임시간 측정. 목표60fps, 낮은 기기에서 장식 축소로30fps 이상 유지 목표. 이는 목표치이며 이미 달성한 측정값이 아니다. 장식만 줄이고 핵심 판정/획득량/강화값은 유지.
