# Claude Opus 5.5 실행 명령 — 마노 게임 통합 재설계 및 수정

너는 지금부터 이미 제작된 ‘마노’ 모바일 웹 액션 로그라이트의 **기존 코드를 수정하는 개발 책임자**다. 새 프로젝트를 만들어 갈아치우는 것이 아니라, 현재 저장소/사이트/기존 데모를 먼저 살펴보고 동작하는 부분은 보존하면서 다음 변경사항을 구현하라. 사용자에게 확인받지 않은 원본 캐릭터 변형, 미구현 기능을 구현한 척하는 UI, 결과물 없이 설명만 하는 답변은 금지한다.

## 0. 작업 시작 전 반드시 할 일

1. 실제 저장소 구조, 기존 게임 파일, 사용 중인 엔진, 저장 데이터 구조, 모바일 해상도 대응, 무기/스테이지/강화/상자/코인 코드를 조사한다. 코드를 읽지 않고 파일명이나 구조를 추측하지 않는다.
2. 기존 GitHub Pages 사이트의 NEWS·ARTIST·DEMO 등 다른 기능과 저장 데이터를 망가뜨리지 않는다. 게임 메뉴의 DEMO 표기도 유지한다. 변경 시 기존 저장 데이터 마이그레이션을 제공한다.
3. 현재 확보된 Astro 제작 이미지와 마노 원본 참고 이미지를 실제로 열어 확인한다. 투명 배경, 스프라이트 프레임 분리, 방향별 형태 일관성, 실게임 해상도에서의 가독성을 점검한다. 품질이 부족한 아트는 코드에서 억지로 회전·확대해 덮지 말고, **교체가 필요한 구체적 파일/프레임만 목록으로 보고**한다. 코드 작업은 병행할 수 있다.
4. 구현의 각 숫자를 설정 파일로 분리하여 나중에 밸런스를 쉽게 수정하도록 만든다. 기획에 적힌 실험값을 실제 게임의 확정 밸런스인 것처럼 포장하지 않는다.

## 1. 절대 바뀌면 안 되는 게임 정체성

- 세로형 모바일 웹, 탑다운 또는 약한 쿼터뷰의 **넓고 평평한 단순 전장**. 공원 분수·벤치·울타리·잡다한 장애물은 제거한다.
- 조작은 **이동용 가상 조이스틱 하나**. 공격·조준·대시 등 액션 버튼을 만들지 않는다. 일시정지 및 메뉴 조작은 예외다.
- 플레이어는 **마노 한 마리**. 자동 공격과 자동 조준. 무기 슬롯은 **하나뿐**이며, 브로테이토의 다중 무기 슬롯은 도입하지 않는다.
- 비픽셀 중심의 선명한 2D SD 그래픽. 마노는 귀엽고, 적들은 실제 괴물처럼 위협적이어야 한다. 효과/환경은 가독성 우선.
- 핵심 재미는 **동일 강화의 반복 선택에 따른 기하급수적 폭증**이다. 평균 운에 막히던 챕터를 ‘이번 판만큼은 핵심 강화가 계속 떠서’ 실제로 돌파할 수 있어야 한다.
- 레벨업 삼지선다(해당 판에서만 유지), 코인으로 기본 스탯을 사는 영구 성장, 중복 장비 합성의 영구 성장은 **각각 별도의 시스템**이다.

## 2. 마노 디자인과 이동 애니메이션 — 최우선 수정

- 반드시 제공된 **마노 원본 그림**의 얼굴·후드 고양이 귀·고양이 후드 일체형 의상·회색/남청색 배색·복부의 밝은 색 영역·목의 붉은 포인트·옷 실루엣을 기준으로 삼는다. 원본에 없는 의상, 다른 캐릭터, 임의의 장식 추가 금지.
- 전투 화면에 실제로 들어가는 작은 SD 스프라이트로 일관성 있게 제작·사용한다. 광고 일러스트나 한 장짜리 일러스트를 캐릭터처럼 평면 이동시키지 않는다.
- idle, 달리기, 피격, 쓰러짐을 구현한다. 이동은 우다다 뛰는 발걸음이 보여야 하며 제자리 미끄러짐/무한 빙글 회전/몸 전체 이미지 회전/방향이 안 맞는 걷기 반복을 금지한다.
- 아트가 충분하면 8방향, 부족하면 **정확한 앞·뒤·좌·우 4방향**을 최소 기준으로 한다. 좌우 대칭 가능 여부는 의상·얼굴 비대칭을 확인해서 결정한다.
- 조이스틱 정규화, 대각선 속도 보정, 즉각적인 방향 전환, 입력 종료 시 자연스러운 정지, 발과 그림자의 접지 위치 고정, 실제 이동속도에 맞는 프레임 재생속도를 적용한다.
- 게임 월드에서 마노는 작게, 전장은 넓게 보이게 설정한다. 카메라와 충돌 박스는 스프라이트의 실제 발 위치에 맞춘다.

## 3. 무기 구조

- **장착 무기는 로비/상태창에서 단 하나 선택**하며, 한 챕터에서 사용하는 무기의 종류는 바뀌지 않는다.
- 최우선은 현재 탱탱볼을 완성하는 것이다. 초기 무기 목표는 총 네 개: ① 탱탱볼(반사 투사체) ② 츄르(고양이 독립 소환수) ③ 비눗방울(장판·지속 피해) ④ 딸랑이(주기적인 원형 음파). 서로 아이콘만 다른 무기가 아니라 공격 알고리즘이 달라야 한다.
- 아직 이미지나 로직이 준비되지 않은 무기는 **상자 추첨 대상에서 제외**한다. 획득만 되고 플레이할 수 없는 무기를 지급하지 않는다. 무기 4종을 하루 만에 억지로 가짜로 완성하지 말고 탱탱볼 완성 → 다른 무기 순으로 구현하되 무기 데이터/이펙트/강화는 확장 가능하게 설계한다.
- 탱탱볼은 실제 2D 전투의 좌표/속도/충돌 법선에 따라 튕겨야 한다. 정해진 포물선 장식이나 화면 전체를 가로지르는 장문의 무지개 트레일 금지. 충돌·반사할 때 짧고 명확한 잔상/타격 피드백을 준다. 열린 평지이므로 화면 끝/논리적 아레나 경계만 반사 대상으로 사용하며 가짜 벽 오브젝트를 추가하지 않는다.
- 탱탱볼 숫자는 ‘한 번에 나가는 공의 수’, 공격주기는 ‘그 묶음을 다시 발사하는 간격’을 뜻하도록 분명하게 코딩한다.

## 4. 삼지선다: 반드시 실제 곱연산, 무제한 재등장

### 핵심 강화 (탱탱볼)

- 공 개수: **현재 값 ×2** (1→2→4→8→16→32→64→128 …)
- 공격주기: **현재 값 ×0.7** (1.0초→0.7→0.49→0.343→0.2401 …)
- 공격 피해량: **현재 값 ×1.5**
- 최대 반사 횟수: **현재 값 ×2** (기본 1회라면 1→2→4→8→16 …)

같은 강화는 같은 챕터의 다른 레벨업에서도 계속 등장할 수 있고 계속 선택 가능해야 한다. ‘이미 골랐으므로 후보에서 삭제’하거나 ‘5회 이상은 나오지 않음’ 같은 제한 금지. 한 번 열린 삼지선다 창 안에서는 **서로 다른 3개 선택지**를 제시한다. 코어 강화 4개에 HP·이동·치명타·투사체속도·크기·흡수범위 등 의미 있는 범용 강화 12개를 더한 **총 16개의 동일 가중치 풀**을 1차 실험 기본값으로 한다. 무기별 코어 4종은 장착 무기에 맞게 교체할 수 있는 구조로 설계한다.

- 설정값 외의 몰래 적용되는 성장 소프트캡·성장률 감소·가짜 숫자 표시 금지. 실제 공격주기, 발사량, 명중 피해가 이 수식대로 적용돼야 한다.
- **로그 지표**: `volleyCount = baseVolley × 2^n_count`, `cooldown = baseCooldown × 0.7^n_interval`, `damage = baseDamage × 1.5^n_damage`, `bounceLimit = baseBounce × 2^n_bounce`.
- 영구 성장 및 장비 등급의 보정은 위 공식에 별도 곱연산으로 합성한다. 챕터가 끝나면 삼지선다 누적치는 초기화, 로비 영구 성장과 무기 등급은 유지.
- 레벨업 중 전투를 멈추고 선택 후 즉시 변화가 적용되게 한다. 임의의 자동 선택, 의미 없는 선택지, 현재 무기에 적용되지 않는 옵션 금지.

### 운빨 고점 보존 + 성능 최적화

- 실제 논리상 공 개수·화력·반사 효과는 ×2로 계속 커진다. 16→32→64 같은 중첩이 진짜 게임 결과에 반영되어야 한다.
- 모바일에서 수백~수천 개 독립 렌더 객체가 생길 수 있으므로 풀링·공간 분할·이펙트 LOD·충돌 배치 처리·필요시 논리 투사체 집계를 설계한다. **보이는 오브젝트 수를 줄일 때에도 실제 명중 가능성/총 피해를 몰래 잘라서는 안 된다.** 집계 처리가 기존 물리/공간 판정을 왜곡하는지 자동 테스트로 비교하고, 성능상 불가피한 근사값은 사용자에게 수치와 함께 공개한다.
- 텔레메트리에 실제 발사된 공 수, 명중 공 수, 유효 DPS, 화면 내 최대 동시 공 수, 프레임 시간, 처치율을 기록한다.

## 5. 밸런스 계산을 반영할 것 — 실측 전의 초기 수치 모델

다음은 **Python/NumPy로 난수 시뮬레이션 20만 판을 실행한 분석 기준**이다. 실제 게임의 승률이 아니다. 함께 전달되는 `mano_balance_simulator.py`로 재현 가능하다.

가정:
- 한 챕터에서 레벨업 선택 18회
- 강화 풀 16개, 매번 **중복 없는 3개**를 균등 추첨, 다음 레벨업에는 재등장 가능
- 예시 선택 정책: 공×2 > 공격주기×0.7 > 피해×1.5 > 반사×2 > 기타
- 분석용 지수 `P = 2^a × 1.5^d ÷ 0.7^c × H(2^r)/H(1)`
- `H(b) = 1 + 7(1-exp(-b/7))`은 **반사탄이 항상 추가 적을 맞히지는 않는다는 점을 나타낸 추정식**이다. 게임 코드의 반사 횟수 제한값이 아니다.

결과(시작 화력 대비 분석상 유효 화력 지수):
- 하위 5%: 약 **27.5배**
- 중위 50%: 약 **164.5배**
- 상위 10%: 약 **681.8배**
- 상위 1%: 약 **2,262.6배**
- 한 가지 특정 강화(공×2)가 삼지선다에 한 번 나올 확률 **3/16 = 18.75%**
- 18번 중 공×2가 **6번 이상 제시될 확률 약 10.42%** (제시될 때마다 골랐다고 가정하면 64배)

지수 550을 어려운 장벽의 **가상 기준값**으로 놓으면, 이 모형에서 넘는 비율은:
- 첫 도달 기본 상태: **약 14.5%**
- 영구 공격력/기본 스펙 효과가 합쳐져 1.25배면: **약 19.3%**
- 1.5배면: **약 23.8%**

**중요**: 위 550은 보스 HP 550이 아니다! 지수와 게임 피해/체력은 단위가 다르다. 이 모델을 근거로 실제 보스 HP를 550으로 설정하지 말고, 실제 적 밀도·명중률·이동 실력·피해 교환을 측정해 난이도를 따로 보정해라.

챕터별 첫 도달 시 목표 실제 클리어율(초기 실험 목표):
- 챕터 1: 90~95%
- 챕터 2: 85~95%
- 챕터 3: 80~90%
- 챕터 4: 45~65%
- 챕터 5: 10~20% (평균 플레이는 막히지만 행운의 빌드는 돌파 가능)

챕터 5에서 일정 기간 영구 스탯을 올린 뒤에는 보통 운으로도 점차 클리어 가능해야 한다. **막힘은 높은 난이도 때문에 발생해야지 스크립트에 의한 강제 패배로 만들면 안 된다.** 승률 목표는 봇 전략과 실제 사용자 실력에 의존하므로, 여러 이동·강화 정책에서 검증하고 조절한다.

검증용 도구를 추가한다:
1. 고정 시드로 삼지선다 선택지 생성·중복 누적 검증.
2. 최소 5만~20만 판 강화 시뮬레이터에서 분위수/스택 발생률 검사.
3. 가능하면 전투를 빠르게 돌리는 자동 플레이 테스트에서 클리어율, 평균 생존 시간, 보스 잔여 HP, 획득 레벨, 코인 획득량을 수집한다. 이동 실력이 다른 봇(최소 2가지) 기준으로 비교한다.
4. `balanceConfig` 한 파일에서 난이도·드랍률·공격계수·영구 스탯 가격을 조정 가능하도록 한다.

## 6. 챕터 구조 — 엘리트 2회 + 보스 1회

- 한 챕터는 우선 약 4분의 웨이브 전투를 기본으로 시작한다(실측 후 변경 가능).
- 일반 몬스터만 끊임없이 나오는 구성 폐기.
- 권장 출현: **70초 엘리트/보너스 빌런, 145초 두 번째 엘리트/미니보스, 210초 챕터 최종 보스**.
- 엘리트 두 종류는 외형/이동/공격·보상이 분명히 달라야 한다. 보스는 더 큰 실루엣·명확한 위험 공격 예고·보스 체력 바를 갖는다. 기존 일반 몬스터 확대 복사만으로 대체하지 않는다.
- 최종 보스를 실제 처치해야 클리어한다. 단순히 제한 시간을 버텼다고 클리어 처리하지 않는다. 시간이 끝났는데 보스가 남아 있다면 보스전 연장/타임오버 규칙을 명시적으로 적용한다.
- 몬스터는 마노와 달리 위협적인 괴물 디자인(임프, 거미, 악마형 진흙, 해골 짐승 등). 귀여운 토끼·고양이를 적으로 쓰지 않는다.
- 공격 패턴은 조이스틱 회피만으로 대응 가능한 범위에서 만들고, 피격 사전 예고는 명확하게 한다.

## 7. 클리어/중간 보상 대폭 확대

‘챕터 깨고 보상 상자 하나’ 구조를 폐기한다. 1차 실험용 보상:

- 엘리트 1 처치: 상자 **1개** + 코인
- 엘리트 2 처치: 상자 **1개** + 코인
- 최종 보스 처치: 상자 **2개** + 코인
- 챕터 클리어: 상자 **2개** + 클리어 코인
- 챕터 **최초 클리어 보너스: 상자 2개 추가**
- 따라서 두 엘리트를 잡고 최초 클리어하면 **총 상자 8개**, 재클리어면 6개를 받는다. 실제 콘텐츠 속도와 경제 밸런스 테스트에서 조정 가능해야 한다.
- 보상 화면은 '상자 개수 + 획득 아이템/코인'을 확실히 보여주고, 상자를 연속으로 열거나 전체 열기를 지원한다.
- 도중 패배해도 이미 획득/습득한 코인, 처치한 엘리트의 획득 확정 보상은 유지한다. 중복 지급 버그를 막기 위해 보상 획득 이벤트를 한 번만 저장한다.
- 경험치 원석은 **챕터 내 레벨업용**으로만 사용하며 게임 종료 시 초기화한다. 코인은 **계정 영구 재화**로 유지한다. 보상 타입을 섞지 않는다.

### 상자 내용과 A등급 첫날 접근성 — 확률 검산 완료

완성 무기 **4종이 실제로 플레이 가능할 때** 사용할 초기 실험안:
- 상자 1개에서 **무기 3회 추첨**, 각 추첨의 무기 종류 4개 균등 확률.
- 등장 등급: D 85%, C 12%, B 3% (합계 100%).
- 같은 무기 같은 등급 3개 합성: D×3→C, C×3→B, B×3→A, A×3→S, S×3→SS, SS×3→SSS, SSS×3→EX. 확장 등급은 이후 설정 파일에서 추가할 수 있게.
- D 1개 가치=1, C=3, B=9, A=27개 D 환산. 다른 무기끼리 합성할 수 없다.
- 시작 시 선택 무기 D 1개 지급. 챕터 2·4 최초 클리어 때 **장착/선택한 무기의 C등급을 1개씩** 추가 지급.

20만 판 강화 계산과 별도로 **10만 번의 상자 추첨 시뮬레이션** 결과:
- 챕터 1~4를 최초 클리어해서 상자 32개(무기 96회 추첨)를 받는 경우, 시작 D 1개 포함해서 '처음 선택한 특정 무기'를 A까지 합성할 확률 약 **86.0%**.
- 여기에 챕터 2·4의 선택 무기 C 두 개까지 합치면 약 **97.7%**.
- 즉 **첫날 A급 달성이 충분히 가능**한 구조다. 이것은 4개 챕터를 실제로 최초 클리어한 경우의 조건부 확률이며, 플레이 시간·실제 클리어 난도·추후 확률 변경에 따라 달라진다.

아직 탱탱볼 하나만 실제 구현돼 있다면: **없는 3개 무기를 상자에 넣지 말 것.** 임시로 상자당 탱탱볼 1회 추첨 + 코인 보상으로 운용하며, 무기 4종 완성 시 위 '상자당 3회 추첨'으로 전환한다. 무기 종류가 바뀔 때 경제 확률을 반드시 재시뮬레이션한다. 상자를 열어도 아무 쓸모없는 아이템이 나오는 상황을 피한다.

## 8. 코인으로 마노 기본 스탯 영구 강화하는 상태창 신설

기존 게임에서 드랍되는 코인이 쓸모없던 문제를 해결한다. 로비에 **'마노 강화'** 화면/상태창을 만들고, 스탯마다 개별 레벨·강화 버튼·현재 수치→다음 수치·필요 코인·잔액을 보여줘라. 공격력 전체 레벨 일괄 상승 방식은 금지, 개별 투자 방식이다.

초기 실험값(각 능력치는 개별 영구 레벨 `L`, 시작은 0):
- 최대 체력: `기본 HP ×1.08^L`; 첫 구매 100코인
- 공격 피해: `기본 피해 ×1.04^L`; 첫 구매 150코인
- 이동속도: `기본 이동속도 ×1.015^L`; 첫 구매 120코인
- 공격주기: `기본 공격주기 ×0.98^L`; 첫 구매 180코인
- 치명타 확률: `기본 확률 + 0.75%p ×L`; 첫 구매 200코인
- 코인 획득량: `기본 코인 보상 ×1.04^L`; 첫 구매 220코인

각 스탯의 다음 구매 가격은 `floor(해당 스탯 시작가격 ×1.35^현재레벨)`로 한다. 예: 100코인 시작 스탯을 연속 구매할 때 **100→135→182→246→332코인**, 처음 4번의 합계는 **663코인**. 첫 챕터 클리어와 도중 코인 드랍을 합쳐서 초반에 대략 3~4회 스탯 구매가 가능하도록 코인 수급을 실측 조절한다. 과도한 코인 인플레이션 없이 초반에는 자주 강화 버튼을 누를 맛을 주고, 나중에는 비용이 빠르게 오른다.

- 체력/공격/이속/공격주기 강화는 선택한 무기의 전투 시작 능력치에 실제로 반영한다.
- 치명타는 합리적인 최대치(예: 영구 치명타 확률 50% 상한)를 명시하고, 이동속도도 조작 가능성 때문에 별도 표시형 상한을 둘 수 있다. 이것은 **영구 스탯에 대한 게임성 제한**이며 챕터 중 핵심 곱연산을 몰래 막는 제한이 아니다.
- 코인은 적/엘리트/보스/클리어 보상에서 수급한다. 패배 시에도 이미 습득한 코인은 보유. 경험치 원석과 혼동하지 않는다.
- 잔액 부족 시 비활성화·명확한 안내, 중복 탭 이중 구매 방지, 저장/불러오기·새 버전 데이터 이전 검증.

## 9. 장비 등급·인벤토리·영구 성장

- 무기 인벤토리는 무기 이름/등급/수량 단위로 관리하며, 같은 무기 같은 등급 3개가 모이면 합성 버튼이 활성화된다.
- 장착 무기 슬롯은 언제나 하나이며, 장비 등급은 **챕터 입장 기본 성능**에 영향을 주고, 챕터 삼지선다 중첩은 매 판 다시 획득한다.
- 등급 성장의 MVP 시작 보정값 예시(실험치, 반드시 설정화): D 1.00, C 1.15, B 1.35, A 1.65, S 2.15, SS 3.00, SSS 4.50, EX 7.00. 각 무기의 고유 공격 메커니즘은 유지하고 등급별 강화 기능은 나중에 추가 가능하게.
- 상자를 연 결과가 인벤토리에 즉시 정확히 반영되고, 합성한 뒤 수량이 3개 감소·상위 아이템 1개 증가하는 원자적 저장을 구현한다.
- 같은 종류가 아닌 무기 사이의 합성, 다른 등급 혼합 합성 금지. 보유 아이템의 등급/수량을 UI에 보여준다.

## 10. 화면/UX 변경

- 전투 화면 HUD: HP, 경험치, 챕터/시간/보스 체력(등장 시), 일시정지, 현재 장착 무기 1칸, 왼쪽 아래 이동 조이스틱만 간결하게 표시.
- 레벨업: 세 장의 카드에 **'탱탱볼 개수 ×2', '공격주기 ×0.7'** 같은 숫자를 정확히 표시. 강화 선택 직후 공 수·발사 속도 차이를 바로 볼 수 있어야 한다.
- 로비 메뉴에 상태창/코인 스탯 투자, 장비창, 상자 개봉, 챕터 선택을 명확히 나눈다.
- 마노의 기본 이미지/동작을 우선 고치고 그 다음 UI를 꾸민다. 임시 이모지·단색 원·저품질 스케치로 원본 캐릭터를 대체하지 말 것.

## 11. 완료 기준 및 테스트 (코드로 검증)

필수 통과 시나리오:
1. 조이스틱만으로 360도 이동, 공격/대시 버튼 없음. 대각선·터치 종료·화면 방향 변경 시도에서 이동이 정상.
2. 마노가 원본 의상을 유지하고 실제 발걸음 애니메이션을 사용. 걷기 프레임과 이동 방향이 일치.
3. 한 판에서 공×2를 5번 연속 선택하면 **논리 발사량 1→2→4→8→16→32**. 공격주기×0.7을 4번 선택하면 1초 기준 **0.2401초**.
4. 강화가 매 판 초기화되지만 코인·영구 스탯·무기 등급/재고는 유지.
5. 특정 강화가 이전에 나왔어도 다음 삼지선다에 재등장. 같은 창 안에서는 3개 카드 중복 없음. 전체 풀 가중치를 데이터와 비교해 검증.
6. 한 챕터 내 엘리트 2명과 최종 보스가 등장하고, 실제 처치에 따라 보상이 달라짐. 보스 생존 중 자동 클리어 금지.
7. 최초 클리어 기준 최대 8상자가 보상으로 보이고, 개봉→인벤토리→동일 3개 합성→장착까지 연결됨.
8. 코인 획득/패배 후 보존/개별 스탯 투자/가격 증가/게임 재시작 후 영구 저장이 정상.
9. 고점 강화 빌드에서 모바일 FPS를 측정하고 렌더 부하로 멈추지 않도록 최적화한다. 효과 축약이 실제 화력 축소로 이어지는지 검증한다.
10. 챕터 1~5의 실제 플레이 로그 또는 자동 봇 결과로 난이도 조절 근거를 제시한다. 수학 모델의 14.5%를 실제 승률이라고 주장하지 않는다.
11. 기존 사이트의 게임 밖 탭/링크/콘텐츠와 이전 저장 데이터가 유지된다.

## 12. 작업 순서 및 결과물

우선순위 P0: 원본 마노 자산 확인·캐릭터/이동·조이스틱 버그 해결 → 탱탱볼 충돌 및 4개 핵심 곱연산 강화 → 강화 추첨 재설계 → 엘리트/보스 2+1 구조 → 보상 확장 → 코인 영구 스탯창 → 합성/저장 검증.

P1: 네 무기 중 남은 츄르/비눗방울/딸랑이 실제 전투 알고리즘·아트·강화 추가, 4무기 랜덤 상자 경제로 전환. **P0를 불완전하게 두고 P1로 넘어가지 말 것.**

최종 산출물에는 다음을 반드시 포함한다.
- 기존 코드 어디를 어떻게 변경했는지 파일별 diff 또는 커밋 요약
- 실제로 실행되는 게임 코드와 실제 플레이 테스트 방법
- `balanceConfig` 등 모든 조정 가능한 상수/설정 파일
- 시드 고정 강화 시뮬레이션/전투 테스트/장비 경제 검증 결과
- 마노 스프라이트 등 아트 품질 확인 결과와 부족한 애셋 목록
- 테스트 통과/실패를 구분한 체크리스트, 남은 문제를 숨기지 않은 보고

**중요: 예쁜 표지 제작으로 문제를 덮지 말 것. 사용자가 지금 원하는 것은 기존 마노 게임이 실제로 귀엽게 움직이고, 같은 강화가 운 좋게 반복되면 말도 안 되게 강해지며, 엘리트와 보상을 통해 계속 도전하고 싶어지는 ‘작동하는 게임’이다.**
